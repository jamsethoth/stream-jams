# Task 9 report — saved Music assets

Implemented the saved branding/font reference matrix and connected Music to the existing asset lifecycle. `collectMusicAssetReferences(config)` returns one `MusicAssetReference` for every non-null branding, title-font, and details-font ID in Landscape/Vertical × full/compact, regardless of selected or visible view. Each reference carries `assetId`, `moduleId: "music"`, `ownerId` (profile), `ownerName`, `variantId` (view), and `usageRole` (`branding` / `title-font` / `details-font`). The core index exports this collector and `MusicPublicAssetReference`.

`AssetLibraryService` now accepts `getMusicConfig?: () => Promise<MusicModuleConfig | null>`, so library items and change impact expose exact Music owners and deletion is blocked while referenced. `validateMusicAssetReferences(config): Promise<void>` rejects missing, unavailable, or incompatible IDs; branding accepts only available PNG/JPEG/WebP image records and fonts only available TTF/OTF/WOFF/WOFF2 font records. `InvalidMusicAssetReferenceError` extends `InvalidOverlayModuleConfigError`, includes the owner and reason, and maps to the existing 400 save response. Runtime composition invokes validation before saving any Music config, including disabled views, inside the serialized media mutation. Existing upload limits and transparent raster handling were untouched.

`AssetLibraryService.resolveMusicAssets(config, targetProfileId): Promise<{ assets: readonly MusicPublicAssetReference[]; missingAssetIds: readonly string[] }>` reads current metadata/health for both views of the requested profile, deduplicates shared IDs, and returns versioned references only for valid available assets. Missing or corrupt after-load references are omitted and reported in `missingAssetIds`, allowing management diagnostics while the renderer uses native fill/system font fallback. The current version is recalculated on each call, so compatible replacement changes projection versions. Music replacement compatibility is checked before import: a referenced brand cannot become GIF/audio/font, and a referenced font cannot become an image. Existing asset retirement and version pinning remain intact.

For exact-version management preview, `POST /assets/:assetId/preview` accepts optional `{ "snapshot": MediaVersionSnapshot }`. If supplied, it requires a matching path ID and current version/metadata and issues a strict preview; stale snapshots return 404, malformed snapshots 400. `MediaPreviewService.createVersioned(sessionId, snapshot)` and `LocalMediaService.acquire(..., expectedVersions)` perform this check within the media mutation queue. Strict renewals recheck current version. Successful replacement calls `MediaPreviewService.invalidateAsset(assetId)` after the serialized mutation to revoke strict old-version grants; ordinary existing preview semantics are unchanged.
