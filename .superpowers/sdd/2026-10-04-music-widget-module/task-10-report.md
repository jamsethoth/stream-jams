- `MusicOutputRuntime.getModuleSnapshot(request)` returns `{ moduleId: "music", enabled: true, instructions: [], presentation?: { kind: "music-widget", widget } }`. Module outputs accept Landscape and Vertical; the legacy profile-less module and unified output use Landscape. Live reads only `MusicRuntimeCoordinator.getProjection`; test uses a local fixed fixture with `artworkRef: null` and never starts or reads a provider. A changed runtime revision during saved-asset resolution discards the obsolete presentation. Versioned uploaded references come from `AssetLibraryService.resolveMusicAssets` and populate `widget.assets`; artwork remains an opaque snapshot reference, outside the uploaded asset table.
- The existing HTTP composition and WebSocket paths serve Music under the same exact output-key rules as other modules. `OverlayOutputManagementService.listOutputs` exposes Music legacy/Landscape/Vertical × live/test and unified live/test. Runtime composition publishes current live Music changes to matching module and unified recipients; config and replacement updates also refresh test fixtures. A new browser recipient fetches its full current composition when its socket opens. Music publication checks the current coordinator revision after asynchronous composition before sending.
- `createOverlayMusicArtworkUrl(route, ref)` in `apps/web/src/overlay/overlay-client.ts` returns a profile-preserving live module or unified artwork URL, or an empty string for test, non-Music, or malformed references. Task 11 should use it in `OverlayApp` through the typed `MusicAssetResolver.resolveArtwork(ref, snapshot)` boundary. `resolveAsset` uses the existing versioned `createOverlayAssetUrl`. A test fixture has no provider artwork.
- Private sync adds optional `artwork` to `DesktopModuleSync`: the trusted worker/main shape is `{ ref, grant: { handle: "mart_...", expiresAt } }`; the renderer shape is `{ ref, handle: "private_..." }`. Both schemas require the ref to match `presentation.widget.snapshot.track.artworkRef`, with no artwork on a cleared presentation. `OverlayHost` translates the service grant through `PrivateOverlayWindow.issueArtwork` into a new private handle. The renderer URL helper `privateDesktopMusicArtworkUrl(artwork)` returns `stream-jams-overlay://surface/music-artwork/private_...`. Task 11 should expose this to the Music renderer in `DesktopOverlayController`/`DesktopOverlayApp` alongside existing versioned asset URLs, disposing the old module revision on clear/replacement. The private protocol proxies verified raster bytes from the fixed owned loopback service and revokes its handles by module owner or window shutdown; it never sends a `mart_` handle to renderer IPC.
- `DesktopModuleSnapshotSink.syncMusic()` sends independent Music revisions only when the selected desktop surface is enabled and its Music layer is explicitly visible. It validates membership again before issuing a private art grant, resolves saved brand/font versions with `DesktopVisualAssetResolver.resolveMusicModule`, and clears/revokes on hidden layer, absent projection and shutdown. `/media/music-artwork/:handle` additionally checks current selected-surface membership at read time. Task 12 can use coordinator status and management artwork without a desktop grant; Task 13 can use the fixture projection and strict versioned preview; Task 15 should verify pixels/input and wrong-output/revoked-key behavior end to end.
