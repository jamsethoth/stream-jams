## Context
Approved in chat 2026-10-03; user authorized implementation with GPT-6.1 Sol low-effort subagents. Baseline origin/main, isolated codex/automation-controls. Plugin is separate and its internal types do not constrain wire format.
## Goals / Non-Goals
Implement secure scoped automation plus timer/queue controls and explicit pairing UI. No plugin edits, publishing, LAN, durable command replay, or manual-secret integration. User waived legacy mute compatibility.
## Decisions
Use existing Fastify, Zod, SQLite and node:crypto; no custom cryptography or new dependency. Thin routes delegate to domain services. Version /automation/v1; legacy timer bearer remains timer-only. Loopback peer + Host validation, reject Origin on machine routes, bounded limiter and body size. Pairing is 5-minute pending request, random verifier with S256 challenge, 8-character comparison code, explicit management-authenticated/CSRF approval; proof required for status/exchange; one successful exchange; grants store hashes, scopes, metadata, revocation. Pending requests memory-only and bounded. Revocation/listing management routes plus credential self-revoke. Exclude grants from export and invalidate on restore. No durable secret in URLs/logs.
Scopes: timers:read, timers:control, playback:read, playback:pause:alerts, playback:pause:screen-effects, playback:skip:alerts, playback:skip:screen-effects, playback:clear:alerts, playback:clear:screen-effects, playback:mute:alerts, playback:mute:screen-effects. Read scope required with related controls.
GET capabilities + GET state return version, runtime identity, state revision/time, granted capabilities and allowlisted state. Mutations require observedRuntimeId; target-sensitive timer commands also expectedGeneration (nullable on activate). Revisions ordered within runtime only; snapshots coherent; commands return changed/outcome + scoped snapshot. Pairing and grants separate from operational services.
Timer activate resolves authoritative status; completed starts immediately. Reset uses latest saved duration but changes only snapshot duration and timing, preserving generation/state/presentation/assets/outputs, silent. Stop/reset/adjust inactive no-op, replacement active generation conflicts. Increment/decrement positive integer ms <=30 days, no inactive creation; zero completes even paused with end cue. Deadline expiration resolved before commands. Bulk toggle any running => pause running; else resume all paused; none => no-op. Shared runtime transition boundary prevents late cleanup resurrection and races with management/events/deadlines. Existing recovery paused/no offline deduction.
Playback module toggles are server-authoritative. Pause blocks next, current continues. Skip binds occurrence, clear binds pending revision/count and preserves current. Empty no-op; stale conflict, never retry automatically. Mute targets explicit authorized module IDs, mixed => mute all, all muted => unmute all. Independent persisted Alerts/Effects mute, All both, cues independent. Remove hidden legacy global gate; no compatibility preservation. All browser/device outputs and current/future playback honor module ownership. Dashboard/tray use same policy; track/report output apply failures.
## Risks / Trade-offs
Cross-output mute delivery may fail: keep saved policy authoritative, expose failure and retry through lifecycle reconciliation, never claim physical silence without evidence. Timer checkpoint failure does not undo live state. Outcome-unknown commands must not be retried; refreshed state is not a receipt. SDK credential storage/hardware acceptance are plugin follow-up dependencies, not server shortcuts.
## Migration Plan
Add grant table excluded from exports. New module mute defaults false; legacy boolean no longer controls playback. Existing timer endpoints retain authority boundaries. Test on disposable databases/output fixtures; no live user data changes. No publishing/merge authorized.
