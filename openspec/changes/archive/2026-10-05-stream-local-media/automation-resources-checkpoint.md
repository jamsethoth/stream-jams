# Repeatable streaming resource acceptance

September 30, 2026. These tests use disposable storage/profiles and generated public-size controls. No user assets, application installation, system file cache, physical audio or visible desktop overlay were changed.

## Durable commands and asserted contracts

- `corepack pnpm test:media-streaming` builds the server, runs resource/recovery server regressions, then forks an isolated actual-built-server worker with `--expose-gc`. The resource tests are also included in ordinary Vitest discovery.
- `corepack pnpm test:desktop:media-streaming` selects the non-hardware packaged format cases. Package prerequisite: a current full Forge build from `corepack pnpm desktop:package`.
- `corepack pnpm test:desktop:media-streaming:hardware` selects muted packaged private-format/resource/recovery cases. Resource acceptance requires one enumerated output, uses zero layer gain and authoritative mute, and suppresses all native window show methods. It is tagged `@hardware` so ordinary desktop CI does not require a physical output. An absent output fails this explicit gate; it is not silently skipped.

`apps/server/src/modules/assets/media-streaming-resources.test.ts` instruments the real opened-file stream's `push` calls without collecting bodies or disturbing backpressure. For **1, 25 and 100 MiB**, each preparation reads the exact full checksum length with maximum chunk **65,536 bytes** and a **65,536-byte high-water mark**. Duplicate references within one preparation hash once. A second preparation using the same owner, and a later owner, each hash afresh. The actual HTTP response helper delivers only **4,096 requested bytes**, returns **206** and the exact interval header, and closes its handle. Owner/grant/service-reader/store-reader counts drain to zero after release. Bulk `store.read()` is prohibited during these playback checks. Capacity tests open exactly **256** readers and issue exactly **4,096** grants, reject one more of each without evicting the owner, and drain all slots afterward.

`scripts/media-streaming-benchmark.mjs` runs the built production service/store/SQLite repositories in a fresh Node worker. Synthetic size fixtures are sparse files: decoder behavior is deliberately outside this benchmark. Every first/repeat preparation reads its full checksum length and every subsequent delivery reads only 4,096 bytes. Each row asserts zero terminal owners/grants/service readers/store readers. Twice-forced GC with event-loop settlement precedes and follows each measurement. The generous regression ceilings are **80 MiB sampled external growth** and **8 MiB post-GC retained external/ArrayBuffer growth**, relative to that row's baseline. These ceilings distinguish a retained large body from ordinary incremental allocation/GC timing; they are not total-process memory promises. Worker IPC is measurement-only, has no body fields or trusted handles, and every envelope is below **4,096 bytes**.

`tests/desktop/media-streaming-resources.spec.ts` exercises the actual Forge ASAR, owned utility service and production private audio renderer. It repeats the same neutral AVC/AAC decoder workload at **1/25/100 MiB** using an appended MP4 `free` box. Each run asserts muted zero-gain native playback, a real private URL, a native interior seek within 150 ms, a real **206** range response, and removal of native audio elements on skip. Captured main-to-renderer audio/overlay IPC rejects body fields and trusted service handles and limits each envelope to **16,384 bytes**. Normal Quit and every captured native PID exit are asserted. Process memory/working-set observations run every **100 ms**; renderer heap is recorded per released playback. Neither sampled native working sets nor renderer totals are brittle pass/fail ceilings.

## Exact scope limits

- Actual file chunk sizes and verification read lengths are direct assertions. Sampled external peaks cannot prove absence of every fleeting allocation between samples. The retained-buffer ceilings and bounded IPC checks provide additional independent evidence; none is a total native decoder memory guarantee.
- Production packaged IPC does not expose utility-process Node external memory or internal grant/read/owner counts. Those exact counters/GC bounds are measured by the isolated actual-built-server worker. Packaged evidence independently covers native teardown, PID exit and protocol transfer. No diagnostic production API was added.
- First process use does **not** mean OS-cache cold. A true cold-OS/storage comparison remains manual; cache flushing or privileged machine-state changes were not attempted.
- Hidden/muted native decoding does not establish audible routing, physical gain/fades, OBS coexistence or visible compositing. Separate tests and manual gates retain their own evidence scope.
- These resource regressions do not complete the whole OpenSpec change, publication gates or canonical spec sync.

Root final combined tagged hardware command passed all three cases; the resource case passed in 6.4 seconds after its final tag adjustment. Native evidence reports normal Quit 356 ms, exit 0 and all captured PIDs exited. See automation-checkpoint.md.
