Supporting output constraints: `packages/core/src/audio/transport.ts` currently carries byte payloads and 25 MiB/100 MiB caps; `apps/desktop/src/audio/audio-player-policy.ts` and `device-audio-player.ts` enforce media/device readiness. `apps/server/src/modules/timers/timer-asset-role.ts` rejects video cues/icons. Unsupported codecs and videos without audio tracks need output-specific failure evidence, never extraction or rerouting. Native GIF readiness does not imply frame-accurate timing.

## Required consistency checks when wiring ownership

- Snapshot checksum, storage/version identity, MIME, size **and duration** in one acquisition. Later metadata repair/replacement cannot alter admitted timing or point a range at new bytes.
- One occurrence/preparation group may have multiple visuals, explicit audio, embedded soundtrack, profiles and devices. Deduplicate by pinned version while keeping recipient grants and cancellation scoped; never pin only visual IDs.
- Reject missing/wrong-media assets atomically; release partial acquisitions and late async resources after timeout/cancel. A no-output rejection, full queue, purge, stale module sync and service restore all need evidence.
- Recent replay semantics need explicit version handling; completion releases active recipients but retained metadata is not permission to play the current replacement under old timing.
- Persistent icon ownership follows run/content revision across hide/re-show/reorder, including browser late join; presentation transport revisions can change more frequently. Timer end-cue ownership can outlive completed-hold visuals.
- Browser/native elements request many ranges. Each range must resolve the same immutable descriptor and be separately cancelled/accounted; HEAD/304 disclose no metadata before authorization. Management bearer tokens never enter media URLs; grant tokens stay out of logs/referrers/exports.
- Revocation cannot silence already-buffered media: authoritative pause/detach/mute/native-stop remains required. File cleanup waits for owners **and** active reads; failed Windows deletion is retryable and must never delete current/unrelated paths.
