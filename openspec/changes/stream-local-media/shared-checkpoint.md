# Shared media checkpoint — September 30, 2026

This is an implementation handoff, not completion or publication evidence. The branch is `codex/stream-local-media-delivery`, following committed HTTP foundation `4c1faa4`. The shared/admission edits below remain uncommitted. No installed runtime, production database, push, or PR was changed.

## Implemented and wired

- `LocalMediaService` retains frozen metadata/duration snapshots, scoped 256-bit grants, owner/grant expiry, cancellation contexts, reader accounting, and generation invalidation. Runtime current management/overlay media reads acquire request owners. `/media/:handle` supports capability GET/HEAD using the shared HTTP adapter; issuance scope comes from the trusted registry, never a request-supplied recipient.
- Admission runs use a server-only `AsyncLocalStorage` scope. `captureAdmission` accumulates immutable versions; repeated lookups in the admission return the same records. Rejection releases its temporary owner; `commitAdmission` transfers ownership to the occurrence before output dispatch.
- Alert automatic admission captures all selected variant and authored layer media before duration/media-type resolution. Saved `AlertEditorService.sendTest` captures its selected records at the same resolution boundary. Queued browser instructions include `assetVersions`.
- Effect explicit/trigger/replay admission captures variant visual/sound metadata and computes its duration from those records before enqueue. The owner commits only after successful enqueue. Default queue terminal callbacks release alert/effect owners on complete/skip/remove/clear. Runtime shutdown invalidates any remaining owners.
- Authorized overlay requests containing `version=<64hex>` acquire the exact current or owned version after existing overlay authentication. Unknown/expired/malformed versions fail closed. Retired owners are filtered to the requested module for module-scoped routes; unified routes retain their existing cross-module scope.
- SQLite migration 029 adds `asset_retirements` and update/delete triggers that record retirement atomically with asset metadata. Replacement routes serialize lookup/validation/import/completion; runtime asset deletion uses the existing atomic SQLite mutation without renaming pinned files. Cleanup waits for owners/readers and checks current paths. Failed cleanup retains intent without changing the outcome of already-committed metadata operations. Explicit reconciliation still reports cleanup failures for diagnostics/tests.
- Restore invalidates contexts/drains opened readers, serializes restore storage work, and leaves old-file deletion to retirement reconciliation. Schema-29 backup compatibility includes supported schema 19–28 archives. This is not yet full restore concurrency acceptance; see remaining work.
- Incremental SHA-256 verification uses 64 KiB buffers and caller cancellation/deadlines. Duplicate destinations share only within one `verifyGroup` call. Each later group hashes freshly. Verified identity evidence belongs to the owner and is compared with subsequent grant opens; no file bytes or successful hash results are cached globally. A second identity-only open detects path replacement during verification.
- The separate preview service/routes are registered with runtime/app. Its close precedes `LocalMediaService.close`. Session invalidation, capped owner TTL, stable renew URLs, and client helpers were implemented by the preview agent; registered preview consumers are a separate continuation.

## Stable integration interfaces

`ownerKey = effectOccurrenceKey(moduleId, occurrenceId) = JSON.stringify([moduleId, occurrenceId])` for alert/effect playback. Timer keys are not wired yet.

- `records(ownerKey, assetIds)` returns the owner's immutable registered records; never substitute current repository lookups in playback preparation.
- `context(ownerKey, assetId)` returns `{record, signal, reader}`. Its reader ignores caller paths/sizes and opens only the captured record. Pass `signal` into streaming delivery.
- `descriptor(ownerKey, assetId)` returns `MediaVersionSnapshot`; `issueTrustedGrant(ownerKey, assetId, recipientId, expiresAt)` returns `TrustedMediaGrant`.
- `verifyGroup(ownerKey, assetIds, signal)` performs fresh integrity work for that preparation group. Issue/use grants only after successful preparation verification for desktop media.
- `release`, `renewOwner`, `renew`, `revoke`, `invalidate`, and `mutate` own lifetime transitions. `counts` exposes owners/grants/readers for bounded diagnostics/tests.
- Version is SHA-256 of internal `storagePath + NUL + registered checksum`; it contains no path. Private desktop references use a distinct `private_` handle. The fixed upstream URL is `/media/<med_ handle>`.
- Desktop continuation's agreed trusted payload is `assets: [{assetId, grant: TrustedMediaGrant}]`; main maps it to separate renderer payload `[{assetId, reference: PrivateMediaReference}]`. Never send `med_` tokens to renderer IPC. Persistent grants need bounded refresh/renewal across long-running timer content and worker generation changes.

## Explicit remaining work for fresh server continuation

1. **Desktop sinks/resolvers are unchanged.** `desktop-audio-sink.ts` and `desktop-visual-asset-resolver.ts` still resolve current records/read bounded whole bodies and enforce the old transport caps. Integrate the owner APIs and trusted grant payloads with the desktop agent. This gap means queue replacement acceptance is not complete for desktop output.
2. **Alert replay remains unowned.** `PlaybackCoordinator.replayRecent` still calls the queue's synchronous replay path. It must reacquire current versions and recompute matching duration/source lengths from retained authored timing metadata, or choose an explicitly justified exact-version replay policy. Completion already releases old pins. Never use replacement bytes with retained old duration.
3. **Effect preparation/browser instruction binding is incomplete.** Admission is pinned, but `EffectPlaybackCoordinator` eligibility and instruction creation still use existing current-record/output paths and do not attach `assetVersions`. Use its occurrence owner for preparation validation and browser/desktop instructions. Replay already passes retained content through fresh duration resolution; preserve authored media-mode semantics.
4. **Timer run/cue/icon ownership is not wired.** Pin run content/media revisions; retain start/end cue and icon versions through relevant run/hold lifetimes. Emit per-card `iconVersion`. Hiding/reordering must not release content ownership. `DesktopModuleSnapshotSink` transport revisions change for visibility and stale async syncs, so they cannot serve as the media-content identity unchanged.
5. **Restore needs a generation/admission fence.** Runtime currently calls `invalidate()` then `mutate(work)` separately inside maintenance. New HTTP/preview acquisition could enter between those operations; add a fence covering the whole restore boundary. `invalidate` snapshots registered read closers before its exclusive cleanup, so a previously queued open may register after that snapshot; settle pending registration before draining. Do not wait for `read.close()` inside the exclusive mutation because close queues its own exclusive accounting. Also check repeated same-archive restore and checksum-based replacement paths do not rewrite an already-owned identical storage path.
6. **Capacity errors need final public classification.** Grants/owners are bounded at 4,096 and file readers at 256; reader capacity has actionable 503. Generic owner/grant exhaustion currently uses unavailable errors. Reconcile the intended bounded-unavailable contract and preview capacity behavior.
7. **Active transport cancellation and acceptance remain.** Signals/read accounting are wired, but native media-element seek, grant revocation while streaming, slow-reader backpressure measurements, interval-only disk-read accounting, and packaged cancellation need final integration evidence. No physical OBS/device acceptance is claimed.
