# Production desktop reference migration checkpoint

September 30, 2026. This supersedes the adapter-only status in `desktop-integration-checkpoint.md` for production desktop transport. Root owns the final cross-layer review, full Forge package and broad publication gates. No commit, push, user installation, user database or private asset modification was performed.

## Production changes

- `packages/core/src/audio/transport.ts` now accepts trusted `{assetId, grant}` worker/main payloads and separately exports `privateAudioPlaybackPayloadSchema` / `PrivateAudioPlaybackPayload`. Registered media bytes, 25 MiB transport ceilings and 100 MiB aggregate budgets are gone. Import ceilings, 64-reference bounds, audio/video source-kind matching, uniqueness, referenced-only validation and timing remain.
- `packages/core/src/overlays/desktop-visual-transport.ts` now separates trusted batches/module snapshots from `privateDesktopVisualBatchSchema`, `privateDesktopModuleSyncSchema`, `privateDesktopVisualCommandSchema` and corresponding types. Renderer envelopes require `protocolVersion: 1` in both directions. Timer assets are unique by `[assetId, version]`, and cards with `iconVersion` require the exact snapshot. The `sync-module` command preserves module validation rather than bypassing refinements through `.shape`.
- Audio main host translates trusted assets through its actual session port before IPC. Each document/preparation gets an independent private owner; stopping a shared playback revokes all its document owners. Completion, failed issue/preparation, prepared timeout, start/play terminal results, stop, destroyed renderer and service loss release the applicable private entries. A first document completion cannot revoke another document's asset. Missing/wrong protocol acknowledgements produce an actionable incompatibility diagnostic.
- The production audio player uses only fixed private native URLs. Native pause/detach remains authoritative alongside registry abort. Preparation expiry stops buffered media rather than releasing a start gate into late playback. Selected-device IDs, per-route failures, existing gain/fades, prepare-before-common-start, actual-onset duration and mute guards remain in the existing engine.
- The fixed routing tone is now a 48,044-byte packaged same-origin resource, generated by `apps/desktop/build-audio.mjs`. Renderer test command uses the production engine. The bounded capability entry point now permits only this fixed resource, 1–16 explicitly supplied device IDs and finite gain 0–2; it deduplicates IDs through one batch. It no longer accepts arbitrary data-WAV bodies.
- Visual main host translates occurrence and persistent timer assets before IPC. New module references are acquired before prior revision references are retired on acknowledgement. Equal-revision server renewal reaches the renderer, retains stable private URLs and extends the registry expiry. Release/stop, preparation expiry, native destruction, service loss and generation discard revoke ownership. Byte accounting/caps were removed from worker and host while bounded counts remain.
- `PrivateMediaProtocol.issue()` renews the same owner/server handle in place, requires an unchanged snapshot and reschedules expiry. Audio and overlay CSP permit only self-origin media/images, without Blob/data permissions. Existing explicit per-read AbortControllers still cancel readers independently of Electron Request signals.

The web owner converted the actual private visual API/controller/App to private references, scoped timer URL lookup by `[assetId, version]`, same-revision renewal and native teardown. The server owner converted actual sinks/resolver to scoped trusted grants and schedules timer renewal; these files were not edited by this desktop continuation.

## Isolated production-class native acceptance

Reproduce after the preceding builds with:

```powershell
node openspec/changes/stream-local-media/desktop-production-media.mjs
```

The launcher copies Electron into ignored `apps/desktop/out/media-acceptance/packaged`, then stages the rebuilt production desktop modules, core/Zod dependency, actual audio player/preloads and actual visual bundle into its disposable `resources/app/runtime`. It reports `app.isPackaged === true`; it is **not** the full Forge/ASAR Stream Jams main/tray/owned-server composition. It uses real `AudioHost`/`AudioWindow` and `OverlayHost`/`PrivateOverlayWindow`, strict production IPC and actual native private sessions/CSP. Upstream HTTP is a narrow test server serving pinned read-only fixture files in 64 KiB chunks with five-millisecond delay and response backpressure, rather than the production grant HTTP service.

Final run passed September 30 around 16:41 local time. Raw results: `apps/desktop/out/media-acceptance/results.json`; process log: `apps/desktop/out/media-acceptance/runtime.log`. ## Remaining acceptance and review boundaries

- Full Forge/ASAR build and main/worker/production-server composition remain root's next integration gate. The new staged native run is stronger than the prior standalone protocol probe, but does not replace that full package check.
- Physical audible selected-device and two-device routing, aliases, OBS/browser-source coexistence, visible transparency, GIF/WebP/audio-container/MP4 index/unsupported-codec/trackless-video matrix, memory measurements and full Quit remain explicitly unverified here. Existing focused player tests preserve routing/alias/gain/fade/timeout/mute/stop semantics; one-device muted native acceptance establishes only the tested path.
- Decoder buffering is separate from application transport. The streaming/IPC evidence does not establish a constant Chromium decoder-memory ceiling or quantify process memory.
- Strict v1 renderer envelope validation plus first initialization/configuration acknowledgement negotiates the private renderer contract. An old preload that silently rejects v1 commands cannot acknowledge; its bounded initialization watchdog emits an explicit protocol-v1-not-acknowledged incompatibility message and destroys the window. Cross-version worker/service composition remains a full-package review concern.
- Timer version-specific schema and adapter renewal are implemented and covered. Final review should verify the server's minute refresh remains bound to each timer run/version rather than timer visibility, and that server cleanup preserves the pinned run owner across refresh.
