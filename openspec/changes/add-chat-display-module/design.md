# Design: Chat Display Module

## Sources

All chat arrives over the existing Streamer.bot connection. Event names come from the [Streamer.bot WebSocket events list](https://docs.streamer.bot/api/websocket/events).

| Platform | Message event | Removal events Stream Jams handles |
| --- | --- | --- |
| Twitch | [`Twitch.ChatMessage`](https://docs.streamer.bot/api/websocket/events/twitch/chat-message) | [`ChatMessageDeleted`](https://docs.streamer.bot/api/websocket/events/twitch/chat-message-deleted) (by `messageId`), `ChatCleared`, `UserBanned`, `UserTimedOut`, `SharedChatMessageDeleted`, `SharedChatUserBanned`, `SharedChatUserTimedout` |
| YouTube | [`YouTube.Message`](https://docs.streamer.bot/api/websocket/events/youtube/message) | `UserBanned`, `UserTimedout` |
| Kick | [`Kick.ChatMessage`](https://docs.streamer.bot/api/websocket/events/kick/chat-message) | `UserBanned`, `UserTimedOut` |
| TikTok | `General` / `Custom` marker from a TikFinity-triggered action | none |

Known gaps, accepted for the first version:

- `YouTube.MessageDeleted` exists, but its docs page shows "No Schema Available", so which field names the deleted message is unknown. Implement it only after a real payload is captured into `apps/server/src/modules/streamerbot/fixtures/`; until then a deleted YouTube message stays until it ages out or the operator hides it.
- Kick has no message-deleted event in Streamer.bot. The community overlay ChatRD gets Kick deletes by connecting to Kick's own Pusher socket ([ChatRD](https://github.com/vortisrd/chatrd), `js/modules/kick/module.js`); that is undocumented and not adopted here.
- No platform has a "clear chat" event except Twitch. `Twitch.ChatCleared` removes Twitch messages only.

The documented example payloads are generated by a schema faker, so field presence must be confirmed from captured real payloads (task 1.1) before the normalizers are finished.

## Intake path

The Streamer.bot runtime gains chat subscriptions that are added only while the Chat module is enabled and the platform is turned on in Chat settings, and only for events Streamer.bot advertises (`GetEvents`), the same rule `consumerExternalEvents` uses today. Disabling Chat unsubscribes them without touching other subscriptions.

In `#handleEvent`, chat and chat-removal envelopes (and the TikTok `ChatMessage` marker) go to the Chat service **before** normalization and are not published to the bus. Reasons:

- The bus journal keeps 10,000 rows for 7 days (`apps/server/src/modules/events/event-bus.ts`). Busy chat would evict real alerts.
- Restart replay would re-deliver old chat to alert rules.
- An unnamed `General` / `Custom` rule fires for every custom broadcast; a TikTok comment marker on the bus would fire it per comment.

Exception: if the user configured an external subscription to a chat event (for example `Twitch` / `ChatMessage` for an alert rule), that envelope is also published to the bus as it is today. Chat display does not change existing rules.

The Chat service never logs message text, author names or image URLs; diagnostics carry platform, event type and a reference ID.

## Message shape

```ts
interface ChatMessage {
  id: string;                 // "<platform>:<platform message id>", or a server UUID when the platform gives none
  platform: "twitch" | "youtube" | "kick" | "tiktok";
  platformMessageId: string | null;
  receivedAt: string;
  author: {
    platformUserId: string | null;
    displayName: string;      // control characters removed, max 64
    color: string | null;     // #RRGGBB only, else null
    roles: Array<"broadcaster" | "moderator" | "vip" | "subscriber" | "member" | "verified">;
    badges: Array<{ label: string; image: ChatImageRef }>; // max 6
    avatar: ChatImageRef | null;
  };
  parts: Array<{ kind: "text"; text: string } | { kind: "emote"; name: string; image: ChatImageRef }>; // text total max 500
  hidden: false | "operator" | "removed";
}
```

- `parts` comes from Streamer.bot's `parts` array when present. Twitch emote parts carry a `source` such as `Twitch`, `BetterTTV`, `FrankerFaceZ` or `7TVChannel`, so third-party emotes need no calls to those services (ChatRD renders them the same way, `js/modules/twitch/module.js`, `getTwitchMessageFromParts`). `Twemoji` parts become text. Cheer parts become text. Unknown part types become their text.
- When `parts` is missing, YouTube falls back to `message` plus `emotes` positions; others fall back to plain text.
- An emote whose image URL is not on the allowlist (below) becomes its text.
- Roles: Twitch from badge names (`broadcaster`, `moderator`, `vip`, `subscriber`); YouTube from `isOwner`, `isModerator`, `isSponsor` (member), `isVerified`; Kick from badge names. The numeric `role` field is not used because its values are undocumented.
- `ChatImageRef` is an opaque server reference, never the remote URL (see Images).

Rendering uses React text nodes and `<img>` elements only. Message text is never parsed as HTML, links are not clickable, and the moderation link rule replaces URLs before display when moderation is on.

## Filters

Applied in the Chat service before a message is stored or shown, in this order:

1. Platform turned off in Chat settings: dropped (it should not be subscribed anyway).
2. Twitch Shared Chat message from another channel (`isFromSharedChatGuest`): dropped while "Show Shared Chat guests" is off (default off).
3. Author in the hidden-accounts list (case-insensitive login or display name, per platform or any platform): dropped. Default list is empty; the editor suggests adding the Streamer.bot bot account.
4. Text starting with `!`: dropped while "Hide commands" is on (default on).
5. Moderation (default on): the active moderation settings' blocked-term replacement and URL stripping (`packages/core/src/moderation/moderation-service.ts`) apply to each text part. Emote names are not moderated.

`isTest` messages from Streamer.bot's test buttons are shown only in the management preview, never on outputs.

## History

- The Chat service keeps the newest 50 accepted messages in a `chat_messages` table (one row per message, JSON parts) and in memory. Insert and trim run in one transaction.
- Removals mark matching rows `hidden = "removed"` (bans and timeouts match platform and `platformUserId`); Hide marks `hidden = "operator"`. Hidden rows are kept until trimmed so a late duplicate cannot reappear, and are never sent to outputs.
- Duplicate `id`s are ignored.
- Clear display deletes all rows.
- On startup the history is loaded as is. Message lifetime (below) still applies, so with a lifetime set, old messages do not reappear after a long restart.
- Chat history is runtime data like playback state: excluded from configuration backup and restore. Avatars, badges and emotes are not persisted; the image cache is memory only and refills on demand.

## Images

Overlay CSP allows images only from Stream Jams (`apps/server/src/http/routes/web-shell.ts`, `apps/desktop/src/overlay/private-overlay-window.ts`). Music artwork already solves the same problem for Pear (`music-artwork-policy.ts`, `music-artwork-service.ts`): an allowlist of public CDN domains, DNS resolution pinned to one public address, bounded body, `sharp` validation, an in-memory LRU and opaque per-recipient references served under module overlay routes.

The fetch, address check, pinned request and bounded body move to a shared module used by both Music and Chat. Chat adds its own policy:

| Purpose | Domains (subdomains included, dot boundary) |
| --- | --- |
| Twitch emotes, badges, avatars | `jtvnw.net` |
| BetterTTV | `betterttv.net` |
| FrankerFaceZ | `frankerfacez.com` |
| 7TV | `7tv.app` |
| YouTube emotes and avatars | `ggpht.com`, `googleusercontent.com`, `ytimg.com` |
| Kick emotes, badges, avatars | `kick.com` |
| TikTok avatars | `tiktokcdn.com`, `tiktokcdn-us.com` |

Differences from Music:

- GIF, PNG, JPEG and WebP are accepted, animated GIF and WebP included, up to 1 MiB, 512 × 512 pixels and 200 frames. SVG is never accepted.
- Cache: 512 entries or 32 MiB, least recently used. Up to 8 fetches in flight; further images show as text (emotes) or nothing (badges, avatars) until fetched, and the output updates when the image is ready.
- A failed or refused image is remembered as failed for 10 minutes so a spammed emote is not refetched on every message.
- References are served at `/overlay/modules/chat/:purpose/:overlayKey/image/:ref` and the unified-surface equivalent, authorized by the overlay key like Music artwork, and to the desktop overlay through the existing private media protocol.

Twitch avatars are not in `Twitch.ChatMessage`. When avatars are on and a Twitch account is connected, the Chat service looks up `profile_image_url` with Helix [Get Users](https://dev.twitch.tv/docs/api/reference/#get-users) (up to 100 IDs per call, no extra scope), batched every 2 seconds and cached in memory for 1 hour. Without a connected account, Twitch messages show no avatar. ChatRD uses decapi.me and Twitch's private GQL endpoint for this; both are rejected (third-party dependency, undocumented API).

## TikTok via TikFinity

TikFinity runs a chosen Streamer.bot action for each TikTok comment and passes `%commandParams%` (the comment), `%nickname%`, `%username%`, `%userId%` and `%profilePicturUrl%` ([TikFinity docs](https://tikfinity.zerody.one/streamerbot-integration)). The Chat editor shows a copyable C# action body:

```csharp
CPH.WebsocketBroadcastJson(JsonConvert.SerializeObject(new {
    source = "StreamJams", type = "ChatMessage", platform = "tiktok",
    userId = args["userId"], userName = args["nickname"], login = args["username"],
    avatarUrl = args["profilePicturUrl"], message = args["commandParams"]
}));
```

Streamer.bot delivers this as `General` / `Custom`. Fields are validated like any provider input (strings, length limits, `platform` must be `tiktok`); anything else is ignored with a diagnostic that does not echo the payload. The `General` / `Custom` subscription already exists while advertised. TikTok has no removal events.

## Outputs

Chat is a visual module like Timers: the server builds one snapshot (visible messages, layout, image references), and the ordinary module browser outputs (landscape and vertical) and the desktop overlay render it, following `output-specific-module-rendering` and `shared-overlay-surfaces`. Browser geometry and desktop placement are separate, as for other modules since #181. Chat has no audio.

Layout settings:

| Setting | Default | Section |
| --- | --- | --- |
| Size and position | lower left, 420 × 600 (landscape) | main |
| Stack direction | newest at bottom | main |
| Maximum visible messages | 10 (1 to 50) | main |
| Message lifetime | 0 (stay until pushed out); 5 to 600 seconds | main |
| Font size | 20 px | main |
| Show avatars | off | main |
| Show badges | on | main |
| Show platform icon | on | collapsed "Appearance" |
| Message background color and opacity | dark, 70 % | collapsed "Appearance" |
| Shadow | shared shadow setting | collapsed "Appearance" |

Each message draws a box, so it uses the shared shadow setting, and the browser-source margin is derived from the shadow (no shadow: the box sits exactly at the edge). Messages enter with a short fade and slide, and leave with a fade; both respect reduced motion. Production overlays fail closed and transparent: a disconnected or failed chat output renders nothing.

## Management and Operator

- Chat section in management with: module enable, platform toggles (Twitch, YouTube, Kick, TikTok) showing whether Streamer.bot advertises each event, filters, the layout editor with a live preview fed by recent messages (or sample messages when none), and the TikFinity setup snippet. Hints when no Streamer.bot source is active, or when a platform is on but not advertised.
- Operator Chat panel: the most recent messages (newest first, including hidden ones, marked), Hide and Unhide per message, Clear display (normal confirmation), and module enable.
