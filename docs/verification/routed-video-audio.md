Audio synthesis connects only to a recording stream, never a device. Playback candidates are tested in the existing packaged private audio window with every media element muted and at volume zero. ## Source normalization

`packages/core/src/audio/media-audio.ts` normalizes explicitly enabled audio and video-soundtrack candidates before visual expansion. It retains logical layer identity and independent volume; separate layers sharing the same asset remain separate. Duplicate layer IDs and invalid kinds, switches, identifiers or volumes are rejected. It does not implicitly disable a soundtrack when separate sound appears. Initial regression: missing-module RED, then 14 passing tests and focused lint. The alert resolver now consumes the helper for Browser Source and device routing.

The resolver now consumes that normalized list for both Browser Source and named device destinations without multiplying soundtracks across visual profiles. WebM and MP4 soundtrack transport retains the 25 MiB asset, 100 MiB batch and five-second preparation limits; stored media type, MIME, actual size and SHA-256 are checked before owned bytes are sent. No playback URL, filesystem path, default device or fallback route is accepted.

Browser, desktop visual and device recipients share one occurrence epoch with a 100 ms scheduling lead. Late media seeks to the current offset; asynchronous seek completion, never-ready/play, expiration, cancellation, mute changes and cleanup are bounded. Alert visual videos remain muted. The Alert inspector's controlled toggle and volume participate in Undo/Redo and explicit Save; separate audio does not change the video toggle, and local preview media follows pause, seek, replay and cleanup ownership.

Automated checks include component and Storybook states, a mocked browser persistence/source-independence workflow, silent packaged codec probes, and a production-path packaged transport probe. These do not substitute for physical-device or OBS acceptance.
